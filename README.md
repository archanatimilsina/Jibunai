# Jibunai

A React Native (Expo) app for the private **ArchanaArea**, wrapped in a native
shell. Splash screen, landing page, and a tab drawer on the right edge.

This folder is a self-contained project. Nothing here reads from the parent
directory, so you can move, copy, or delete `Jibunai/` on its own.

## What is inside

```
Jibunai/
├── App.js                     app shell: splash -> home -> destinations
├── index.js                   Expo entry
├── app.json                   Expo config (name, icon, splash, package ids)
├── package.json               app scripts and dependencies
├── compose.yml                mongo for the backend
├── assets/                    logo + generated app icons
├── src/
│   ├── theme.js               palette, fonts, radii, shadows
│   ├── components/
│   │   ├── AppSplash.jsx      logo + "Jibunai" on launch
│   │   ├── Drawer.jsx         right-edge swipe navigation
│   │   ├── ScreenFrame.jsx    top bar for every destination
│   │   └── *.jsx              the 13 app screens
│   ├── navigation/routes.jsx  every screen + icon + caption
│   └── screens/
│       ├── HomeScreen.jsx     landing page
│       └── WebsiteShell.jsx   ArchanaArea WebView
├── web/                       the ArchanaArea web app (Vite)
└── backend/                   Django API (a full copy)
```

## Running it

```bash
npm install
npm run android     # build the native app and install it on the phone
npm start            # start Metro for the dev client
```

Requirements: Node 20+, Java 17, the Android SDK with `ANDROID_HOME` set, and
USB debugging enabled on the phone.

You do not need the backend to open the app. Point the app at a running API by
setting `EXPO_PUBLIC_API_URL` in `.env`; otherwise the screens show their empty
state.

## The backend

`backend/` is a complete, independent copy of the Django API. It is not
required to build or run the app, but it is here so this project works alone.

```bash
npm run mongo            # docker compose up -d mongo
npm run backend:install  # pip install -r backend/requirements.txt
npm run backend:migrate
npm run backend:start    # http://localhost:8000
```

Fill in `DATABASE_URL`, `DJANGO_SECRET_KEY`, and the Supabase values in
`backend/.env`.

## The web app

`web/` is a standalone Vite app. Build and deploy `web/dist` to any static host,
then set its URL as `EXPO_PUBLIC_APP_URL` in `.env` so the WebView tab loads it.

```bash
npm run install:web
npm run build:web        # outputs web/dist
npm run dev:web          # Vite dev server on http://localhost:5174
```

## Navigation

The menu is a drawer on the right edge. Drag leftwards from the right edge to
pull it in; drag it back right, tap the dimmed page, or press the Android back
button to hide it. A slim handle stays on the edge so it is never hidden.

The landing page lists every place as a card: one column on a phone, two on a
tablet, three on a wide screen.

## Assets

Every icon comes from `assets/jibunai-logo.png`, cut from the Jibunai artwork
with the stray corner marks removed. `icon.png` is the 1024 app icon,
`android-icon-background.png` the adaptive background,
`android-icon-foreground.png` the adaptive foreground,
`android-icon-monochrome.png` the Android 13+ themed silhouette, and
`splash-artwork.png` the launch image (also referenced by `app.json`).

## Other scripts

| script | what it does |
| --- | --- |
| `npm run android` | build and install on a chosen device |
| `npm run android:emulator` | build and install on the emulator |
| `npm run prebuild` | regenerate `android/` from `app.json` |
| `npm run web` | run the Expo app in a browser |
| `npm run ios` | build and install on iOS |
| `npm run backend:check` | run Django's system check |

## Notes

- `android/` and `ios/` are generated by `npx expo prebuild` and are gitignored.
  Delete them and run `npm run prebuild` to rebuild.
- If `EXPO_PUBLIC_APP_URL` is empty, the WebView tab shows setup instructions
  instead of a blank page.
- `web/src/ArchanaArea` is a copy of the desktop app's `frontend/src/ArchanaArea`.
  Keep editing it here for mobile-only tweaks.
- Release builds read `EXPO_PUBLIC_API_URL` from EAS secrets, not `.env`:
  `eas secret:create --scope project --name EXPO_PUBLIC_API_URL --value https://…`
  (the `development` profile hardcodes the emulator at `http://10.0.2.2:8000`).
- `npm run mongo` / `compose.yml` is legacy — nothing in the app uses Mongo;
  the API runs on Supabase Postgres (`backend/.env`).
